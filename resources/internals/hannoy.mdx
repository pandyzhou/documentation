Meilisearch 采用一种基于**磁盘支持的近似最近邻（Disk-backed ANN）**检索架构来存储和搜索高维向量。该架构受微软前沿研究 [DiskANN](https://github.com/microsoft/DiskANN) 的启发，并由 Meilisearch 在 v1.29 版本中自研推出的 **Hannoy** 向量存储库具体实现。

## 什么是 DiskANN？

DiskANN 是一系列用于构建“常驻于磁盘而非全量硬塞进物理内存”的图结构向量索引技术。传统的向量检索引擎（如早期纯内存形态的 FAISS 或 HNSWlib）要求必须将完整的向量索引全部载入 RAM，这在面对千万到亿级高维向量时会导致服务器硬件成本极其高昂甚至根本不可行。

DiskANN 的核心突破在于：通过极其考究的磁盘数据布局，结合图导航算法，**在将数据保存在低成本 NVMe SSD 固态硬盘的前提下，实现了接近纯内存运行的极致检索速度**。

Meilisearch 将这一前沿思想落地：通过结合 **HNSW（分层可导航小世界图）** 的空间导航拓扑与 **LMDB** 的高效持久化，实现了彻底摆脱物理 RAM 容量束缚的高速向量检索。

## Hannoy：Meilisearch 的专用向量引擎

Hannoy 采用 HNSW 作为图结构，LMDB 作为底层持久化引擎，全面替代了旧版本基于超平面树（k-d tree）的 [Arroy](https://github.com/meilisearch/arroy) 引擎。

### 为什么用 Hannoy 替代旧版 Arroy？

| 痛点维度 | 旧版 Arroy (树结构) 的局限 | Hannoy (图结构) 的突破 |
| :--- | :--- | :--- |
| **维度敏感度** | 超过 ~20 维后性能呈指数级断崖式下跌 | 轻松应对 768 到 3072 高维向量 |
| **叶子节点计算** | 必须对叶子节点内的所有向量进行全量暴力比对 | 贪婪图遍历，仅需极少数跳数（Hops） |
| **建索 I/O 损耗** | 超过 90% 的建索时间浪费在磁盘缺页中断上 | 顺序流式写入，I/O 效率提升数倍 |

### 性能飞跃实测（百万级文档基准测试）

#### 768 维向量对比
- **建索耗时**：从 2387 秒缩减至 506 秒（**快 4.7 倍**）
- **搜索延迟**：从 190ms 降至 29ms（**快 6.5 倍**）
- **磁盘占用**：从 16.19 GiB 压缩至 4.03 GiB（**体积缩小 4 倍**）

#### 1536 维量化向量对比
- **建索耗时**：从 141 秒缩减至 67 秒（**快 2 倍**）
- **搜索延迟**：从 168ms 降至 13ms（**快 13 倍！**）
- **磁盘占用**：从 1.86 GiB 压缩至 481 MiB（**体积缩小 4 倍**）

真实案例：某企业级客户的大规模向量建索时间从原本的 2 个月直接锐减到 6 秒！

## 底层工作机制

### 1. HNSW 分层小世界图导航

```text
第 2 层 (顶层):  A -------- D              (稀疏跨度大，实现超远距离高速定位)
                |          |
第 1 层 (中间):  A -- B --- D -- E         (中等密度)
                |    |     |    |
第 0 层 (底层):  A-B-C-D-E-F-G-H-I-J      (全量向量，紧密邻接，局部精准捕获)
```

**检索流程：**
1. 从顶层稀疏图入口进入，以极快速度向查询向量方向贪婪游走；
2. 抵达局部最优极小值后，下潜至下一层；
3. 在最底层的密集图上收敛，输出距离最近的 Top-K 邻居。

### 2. 基于 LMDB 的磁盘常驻优势
- **摆脱 RAM 限制**：数据集容量上限取决于廉价的固态硬盘大小，而非昂贵的内存条
- **内存映射零拷贝**：内核自动管理页面换页缓存
- **并发只读安全**：多检索线程并行并发无锁读取

### 3. 高性能增量实时更新
- **写入新增**：新向量先吸收到内存中的临时缓冲区，积累到阈值后流式合并进磁盘主图，合并时全库仅需微调约 1% 的局部连接边；
- **删除操作**：基于 DiskANN 风格的邻居缝合策略，原地重连受影响的邻居边，无需昂贵的垃圾标记或全图重构。

### 4. 距离度量衡
- **Cosine (余弦距离)**：归一化文本向量的标准首选
- **Euclidean (欧氏距离)**：通用空间距离度量
- **Dot product (点积)**：适用于单位向量的极速点积
- **Hamming (汉明距离)**：用于 1-bit 二进制量化向量的极致高速位运算比较
