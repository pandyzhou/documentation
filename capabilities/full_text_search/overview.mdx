全文检索是 Meilisearch 的核心立足之本。当用户输入检索词时，Meilisearch 会高速扫描[已建索](/capabilities/indexing/overview)的文档，并运用多准则排序算法，按相关度高低返回结果。

## 核心特性

- **[错别字容错](/capabilities/full_text_search/relevancy/typo_tolerance_settings)**：基于莱文斯坦编辑距离（Levenshtein distance），自动智能纠正拼写失误
- **[前缀即搜匹配](/capabilities/full_text_search/how_to/configure_prefix_search)**：随着用户键盘敲击实时返回匹配局部词汇的结果（打字即搜）
- **多准则排序流水线**：串联组合多项[排序规则](/capabilities/full_text_search/relevancy/ranking_rules)（容错成本、词距、属性权重、精确度等），综合决定展示顺序
- **高度可定制的相关度**：灵活配置排序规则、[可搜索字段](/capabilities/full_text_search/how_to/configure_searchable_attributes)、[停用词](/capabilities/full_text_search/how_to/configure_stop_words)、[同义词](/capabilities/full_text_search/relevancy/synonyms)等，深度适配具体业务场景

## 何时采用全文检索？

当用户通过关键词或简短词组进行检索，并期望获得基于文本字面与语义相关度排序的结果时，全文检索是最佳方案。如果你的用户习惯用长句自然语言提问，或者核心诉求是基于抽象语境含义而非精确词汇匹配，请考虑使用[混合检索](/capabilities/hybrid_search/overview)或[智能体对话搜索](/capabilities/agentic_search/overview)。

## 搜索接口的选择：POST 优先

Meilisearch 提供了两条搜索路由：`POST /indexes/{index_uid}/search` 与 `GET /indexes/{index_uid}/search`。**在绝大多数场景下，强烈推荐使用 `POST` 端点。** `POST` 完整支持所有高级搜索参数（包括结构化数组形态的 `filter` 过滤表达式），这也是所有官方 SDK 默认使用的端点。

<Warning>
除非你有非常明确的技术理由（例如必须依赖反向代理或 CDN 层的 HTTP GET 缓存机制），否则不建议使用 `GET /search`。`GET` 路由仅支持字符串形式的过滤表达式，且可能受 URL 长度限制影响。
</Warning>
