## 文本规范化处理 (Normalization)

在建索流水线中，同义词会受到分词器配置（停用词、分隔符等）的统一规范化处理。请确保同义词中不包含分隔符符号（如 `&`），以免在实际匹配中被当作符号过滤掉。

## 单向同义词 (One-way association)

用于将词 A 关联到词 B，但**不反向关联**。

```
phone => iphone
```

- 用户搜 `phone` 时，会同时召回包含 `iphone` 的文档（因为搜手机时包含苹果手机很合理）；
- 但用户搜 `iphone` 时，**不会**召回只写了普通 `phone`（安卓或其他手机）的文档。

JSON 配置格式如下：

<CodeGroup>

```json
{
  "phone": [
    "iphone"
  ]
}
```

</CodeGroup>

## 排序优先级：精确词始终优于同义词

**用户输入的真实精确词永远享有最高优先级。** `exactness` 排序规则会确保：包含用户真正输入的那个词的文档排在前面，而仅仅通过同义词匹配召回的文档位次居后。

例如将 `ghost` 与 `spirit` 设为同义词：
- 用户搜 `spirit` 时，标题为 `Spirit of Justice` 的文档一定排在标题为 `Ghouls 'n Ghosts` 的文档前面。

## 双向互通同义词 (Mutual association)

互相关联的一组同义词在两个方向上地位等价：

```
shoe <=> boot <=> slipper <=> sneakers
```

JSON 配置方式：

<CodeGroup>

```json
{
  "shoe": [
    "boot",
    "slipper",
    "sneakers"
  ],
  "boot": [
    "shoe",
    "slipper",
    "sneakers"
  ],
  "slipper": [
    "shoe",
    "boot",
    "sneakers"
  ],
  "sneakers": [
    "shoe",
    "boot",
    "slipper"
  ]
}
```

</CodeGroup>

## 多词复合短语同义词

Meilisearch 原生支持由多个单词组成的短语同义词，并在匹配时将其视作连续短语（Phrase）：

<CodeGroup>

```json
{
  "san francisco": [
    "sf"
  ],
  "sf": [
    "san francisco"
  ]
}
```

</CodeGroup>

## 数量与长度限制约束

- **词长限制**：Meilisearch 仅对由 **1 到 3 个词**构成的查询词触发同义词扩展。如果输入包含 4 个及以上词汇，将不再展开同义词。
- **单个词的同义词上限**：每个词最多可关联 **50 个同义词**。超出 50 的部分将被静默忽略。
- **总词数上限**：某个词的所有同义词加起来，总词数不得超过 **100 个词**。
