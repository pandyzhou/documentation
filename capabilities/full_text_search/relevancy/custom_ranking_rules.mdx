在 Meilisearch 中有两种排序规则：[内置排序规则](/capabilities/full_text_search/relevancy/ranking_rules) 与自定义业务排序规则。本文详细介绍如何配置和使用自定义规则来满足你的业务排序逻辑。

## 升序与降序规则

Meilisearch 支持两种自定义规则语法：一种用于升序（Ascending），另一种用于降序（Descending）。

添加自定义规则时，输入文档的字段名（Attribute Name），紧跟冒号（`:`），最后指定 `asc`（升序）或 `desc`（降序）：

- **升序排列**（字段数值越小或字母顺序越靠前，排位越高）：`attribute_name:asc`
- **降序排列**（字段数值越大或字母顺序越靠后，排位越高）：`attribute_name:desc`

**该字段在对应索引的所有文档中必须是数值型（Numeric）或字符串型（String）。**

<Warning>
如果索引中有部分文档**缺少**了自定义规则中指定的字段，排序行为将变得不确定，结果可能无法达到预期。请确保被设为自定义排序规则的字段在全量文档中均真实存在。
</Warning>

你可以通过[全量设置更新接口](/reference/api/settings/update-all-settings)或[排序规则更新接口](/reference/api/settings/update-rankingrules)将自定义规则追加到当前规则列表中。

## 如何合理使用自定义规则？

自定义规则按字符字典序（Lexicographical order）或数值大小排序。例如在降序排列中，`Elena` 会排在 `Ryu` 前面，但会排在数字 `11` 后面。

因为这项操作纯粹看字段数值或字典序，**并不考虑文档的文本相关度**，因此在绝大多数情况下，**你应当把自定义规则放在所有内置排序规则之后**。这样能够确保：只有当两篇或多篇文档在文本相关度打分完全相同（平局）时，才会动用自定义规则决胜。

如果你把自定义规则提到很靠前的位置，会导致搜索体验显著退化，因为用户看到的结果将变成冷冰冰的字母序或数值序列表，而非文本契合度最高的内容。

## 业务实战示例

假设你有一批电影数据集。文档包含时间戳字段 `release_date`（上映日期）以及整数评分字段 `movie_ranking`。

以下规则将使老电影排在前面（1999 年的电影排在 2020 年前面）：

<CodeGroup>

```
release_date:asc
```

</CodeGroup>

以下规则将使高评分电影排在低评分前面：

<CodeGroup>

```
movie_ranking:desc
```

</CodeGroup>

完整的黄金排序规则数组如下，将自定义业务规则放在流水线最底部：

<CodeGroup>

```json
[
  "words",
  "typo",
  "proximity",
  "attributeRank",
  "sort",
  "wordPosition",
  "exactness",
  "release_date:asc",
  "movie_ranking:desc"
]
```

</CodeGroup>

## 检索期动态排序 (Sort) 与自定义排序规则的区别

Meilisearch 允许前端在[发起单次查询时传入 `sort` 参数](/capabilities/filtering_sorting_faceting/how_to/sort_results)。虽然它们看起来相似，但使用场景截然不同：

- **单次检索参数 `sort`**：通常由**最终用户主动触发**。例如电商网站中，用户在下拉框里主动选择“按价格从低到高排列”或“按销量从高到低排列”。
- **自定义规则 (Custom ranking rules)**：属于**全局默认商业规则**，常驻生效。例如平台运营方希望在所有文本打分相近的商品中，拥有折扣标记或更高利润率的商品始终优先微调排在前排。
