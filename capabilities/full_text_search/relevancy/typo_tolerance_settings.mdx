拼写容错（Typo tolerance）帮助用户在输入错误字符或打错字母时（例如打错成 `phnoe` 而不是 `phone`），依然能顺利召回相关结果。你可以[针对每个索引单独配置容错行为](/reference/api/settings/update-typotolerance)。

## `enabled`（全局开关）

拼写容错默认开启。如有特殊业务需要，你可以显式将其关闭：

<CodeSamplesTypoToleranceGuide1 />

关闭后，Meilisearch 将不再召回与查询词存在字符微小差异的近似词。例如搜 `phnoe` 将无法再匹配到包含 `phone` 的文档。

**在绝大多数场景下，保持开启容错能够带来好得多的搜索体验。** 仅在极其庞大或混杂多语言的数据集下，偶发误伤（False positives）时才考虑按需调整。

## `minWordSizeForTypos`（错字词长阶梯阈值）

默认情况下，Meilisearch 遵循以下词长规则：
- 单词长度达到 **5 个字符**及以上，允许 **1 个错字**；
- 单词长度达到 **9 个字符**及以上，最多允许 **2 个错字**。

如果你的数据集中包含 `seven`，搜 `sevem` 或 `sevan` 会成功匹配；但搜 `tow` 无法匹配 `two`，因为只有 3 个字符（小于 5）。

你可以通过 `minWordSizeForTypos` 对象覆盖该默认规则：

<CodeSamplesTypoToleranceGuide4 />

配置必须满足数学约束：`0 ≤ oneTypo ≤ twoTypos ≤ 255`。官方推荐将 `oneTypo` 设在 `2` 到 `8` 之间，`twoTypos` 设在 `4` 到 `14` 之间。如果设得太低容易导致大量风马牛不相及的误伤，设得太高则无法享受到容错红利。

<Tip>
**首字母错字加权**：首字符打错在 Meilisearch 底层直接被计为 **2 个错字**。  
**空格粘连处理**：当用户在词语间少打或多打了空格（如把 `anyway` 打成了 `any way`），Meilisearch 会自动将其粘连合并计算，并计为 **1 个错字**。
</Tip>

## `disableOnNumbers`（数字完全禁用容错）

将 `disableOnNumbers` 设为 `true` 可以对所有纯数字禁用容错：

<CodeGroup>

```bash
curl \
  -X PATCH 'MEILISEARCH_URL/indexes/INDEX_NAME/settings/typo-tolerance' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer MEILISEARCH_KEY' \
  --data-binary '{
    "disableOnNumbers": true
  }'
```

</CodeGroup>

默认情况下数字也是参与容错的，这可能导致搜年份 `2024` 时意外命中 `2025` 或 `2004`。将该项设为 `true` 后，数字将仅支持严格完全匹配，还能轻微改善建索性能。

## 底层容错机制原理

Meilisearch 基于前缀[莱文斯坦编辑距离算法（Levenshtein distance）](https://en.wikipedia.org/wiki/Levenshtein_distance)实现容错。两个单词之间的编辑距离代表将词 A 变为词 B 所需的最少单字符操作次数（替换、插入或删除）。

Meilisearch **单个单词最多允许 2 个错字**。无论单词有多长，超过 3 个错字的词绝不会被召回。
