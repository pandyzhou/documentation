`filter` 搜索参数接收一个由字段属性、比较值以及各类运算符组成的**过滤表达式 (Filter expression)**。过滤表达式可以编写为纯字符串、多维数组，或者两者的混合形态。

## 支持的数据类型

过滤器支持数值型（Numeric）与字符串型（String）。空字段或包含空数组的字段在计算过滤时会被自动忽略。

过滤器不支持未序列化的 `NaN` 或无限大值（如 `inf` 和 `-inf`），因为这些并非标准 JSON 数据类型。如果要过滤它们，必须以字符串形式存入。

<Warning>
为了获得最佳的过滤性能和准确性，请确保同一字段在所有文档中保持统一的数据类型。Meilisearch 不强制校验 Schema，但底层的过滤引擎可能会对 `value` 进行类型强制转换。例如当巨大的浮点数被强制转换为整数时，可能会导致预期之外的截断行为。
</Warning>

## 基础条件结构 (Conditions)

条件是构建过滤器的最小积木。它们遵循 `字段 运算符 目标值`（`attribute OPERATOR value`）格式：

- `attribute`：你想要进行过滤的字段名
- `OPERATOR`：支持 `=`, `!=`, `>`, `>=`, `<`, `<=`, `TO`, `EXISTS`, `IN`, `NOT`, `AND`, `OR`, `CONTAINS`, `STARTS WITH` 等
- `value`：该字段需要匹配的目标值

### 基础示例

匹配题材 `genres` 为 `horror`（恐怖片）的电影：

<CodeGroup>

```
genres = horror
```

</CodeGroup>

包含空格的字符串值必须用单引号或双引号包裹：

<CodeGroup>

```
director = 'Jordan Peele'
director = "Tim Burton"
```

</CodeGroup>

## 过滤运算符清单

### 1. 等值匹配 (`=`)

返回指定字段包含目标值的全部文档：

<CodeGroup>

```
genres = action
```

</CodeGroup>

- 对字符串进行比较时，`=` **不区分大小写**（Case-insensitive）。
- 当过滤字段是**数组**时，`=` 会匹配数组中**至少包含一个该元素**的文档。例如若某篇文档为 `"genres": ["action", "adventure"]`，那么过滤条件 `genres = action` 会成功命中该文档。
- 等值运算符不会命中 `null` 或空数组。

### 2. 不等匹配 (`!=`)

返回所有不满足等值条件的文档（同样不区分大小写）：

<CodeGroup>

```
genres != action
```

</CodeGroup>

### 3. 数值与字符串大小比较 (`>`, `<`, `>=`, `<=`)

选择满足比较条件的文档，既适用于数字，也适用于按字典序比较的字符串：

<CodeGroup>

```
rating.users > 85
```

</CodeGroup>

对于日期字符串，按照字典序比较。以下表达式返回所有在 2004 年元旦之后上映的电影：

<CodeGroup>

```
release_date > 2004-01-01
```

</CodeGroup>

### 4. 闭区间范围 (`TO`)

`TO` 等价于 `>= AND <=`，表示一个闭区间。以下表达式返回大众评分在 80 到 89 分之间的文档：

<CodeGroup>

```
rating.users 80 TO 89
```

</CodeGroup>

### 5. 字段存在性检查 (`EXISTS`)

`EXISTS` 检查文档中是否存在某个字段。字段取值为空字符串或 `null` 同样算作“字段存在”。

<CodeGroup>

```
release_date EXISTS
```

</CodeGroup>

反向否定形式有两种等价写法：

<CodeGroup>

```
release_date NOT EXISTS
NOT release_date EXISTS
```

</CodeGroup>

#### 向量数据存在性过滤
在开启 AI 搜索时，可以使用 `EXISTS` 过滤包含向量数据的文档：
- `_vectors EXISTS`：匹配所有生成了向量嵌入的文档
- `_vectors.{embedder_name} EXISTS`：匹配针对特定模型生成了向量的文档
- `_vectors.{embedder_name}.userProvided EXISTS`：匹配包含用户自行上传向量的文档

### 6. 空值检查 (`IS EMPTY` 与 `IS NULL`)

- `IS EMPTY`：匹配字段存在但内容为空的文档（针对 `""`、`[]`、`{}` 生效，不匹配 `null`）
- `IS NULL`：匹配字段存在但显式取值为 `null` 的文档

<CodeGroup>

```
overview IS EMPTY
overview IS NOT EMPTY
overview IS NULL
overview IS NOT NULL
```

</CodeGroup>

### 7. 集合成员检查 (`IN`)

`IN` 相当于多个等值 `=` 的 `OR` 简写语法，方括号内用逗号分隔。匹配包含指定列表中任意一个值的文档：

<CodeGroup>

```
genres IN [horror, comedy]
genres NOT IN [horror, comedy]
```

</CodeGroup>

### 8. 包含子串 (`CONTAINS` - 实验性特性)

<NoticeTag type="experimental" label="实验性特性" />

`CONTAINS` 过滤字段值中包含指定子串的结果，类似于 SQL 中的 `LIKE '%xxx%'`：

<CodeGroup>

```
dairy_products.name CONTAINS kef
```

</CodeGroup>

### 9. 前缀开头 (`STARTS WITH`)

过滤以指定字符开头的文档：

<CodeGroup>

```
dairy_products.name STARTS WITH kef
```

</CodeGroup>

### 10. 逻辑非 (`NOT`)

对紧随其后的条件进行取反。优先级高于 `AND` 和 `OR`：

<CodeGroup>

```
NOT genres = horror
```

</CodeGroup>

### 11. 跨索引外键过滤 (`_foreign()`)

利用跨索引之间的外键 Join 关联，根据关联索引中文档的属性对主索引进行过滤：

<CodeGroup>

```
_foreign(company, id = "company_42")
```

</CodeGroup>

## 复合表达式构建

通过 `AND` 与 `OR` 运算符，可以将多个原子条件自由组合。

### 运算符优先级与圆括号

Meilisearch 从左向右解析字符串表达式。**`AND` 的优先级高于 `OR`**。强烈建议使用圆括号确保逻辑分组符合业务预期：

<CodeGroup>

```
(genres = horror OR genres = comedy) AND release_date > 795484800
```

</CodeGroup>

### 使用数组构建复合过滤器

在 JSON 请求中，可以通过嵌套字符串数组来表达逻辑连接，**最大支持 2 层数组嵌套**：

- **外层数组元素**：彼此之间是 **`AND`** 关系：
  `["genres = horror", "director = 'Jordan Peele'"]`
- **内层数组元素**：彼此之间是 **`OR`** 关系：
  `[["genres = horror", "genres = comedy"]]`
- **内外层自由组合**：
  `[["genres = horror", "genres = comedy"], "director = 'Jordan Peele'"]`  
  *(意为：题材是恐怖片或喜剧片，且导演是乔丹·皮尔)*
