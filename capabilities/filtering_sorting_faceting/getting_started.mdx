本教程通过一个虚拟的电影数据集，带你学习如何在 Meilisearch 中配置和运用过滤器（Filters）。

## 配置索引设置

假设你有一批名为 `movie_ratings` 的电影集合，文档包含以下字段：

<CodeGroup>

```json
[
  {
    "id": 458723,
    "title": "Us",
    "director": "Jordan Peele",
    "release_date": 1552521600,
    "genres": [
      "Thriller",
      "Horror",
      "Mystery"
    ],
    "rating": {
      "critics": 86,
      "users": 73
    }
  },
  …
]
```

</CodeGroup>

如果你希望在搜索时允许对某个字段执行过滤，**必须首先将其加入到 `filterableAttributes` 列表中**：

<CodeSamplesFilteringUpdateSettings1 />

**这一步是绝对必需的前提，无法在查询发起时临时完成**。更新 `filterableAttributes` 会触发 Meilisearch 对数据在底层构建专用的过滤索引结构，耗时取决于数据集的大小与复杂度。

<Note>
默认情况下 `filterableAttributes` 是空的。如果不提前显式添加字段，在搜索请求里传入该字段的 `filter` 表达式将直接报错。
</Note>

<Tip>
计算像 `<`, `>`, 或 `TO` 这样的**数值比较过滤**相比等值比较更消耗计算资源。只在真正需要的数值/时间字段上开启比较。对于字符串标签，仅开启等值过滤 `equality` 性能更好。你可以使用[细粒度可过滤属性配置](/capabilities/filtering_sorting_faceting/how_to/configure_granular_filters)按需微调每个字段所支持的操作符。
</Tip>

## 在搜索时使用 `filter` 参数

更新好 [`filterableAttributes` 索引设置](/reference/api/settings/get-filterableattributes)后，即可在搜索请求中传入 `filter` 参数来细化结果。

`filter` 接收由 `filterableAttributes` 中已登记字段构建的[过滤表达式 (Filter expressions)](/capabilities/filtering_sorting_faceting/advanced/filter_expression_syntax)。

你还可以组合多个复杂的布尔条件。例如仅检索由 `Tim Burton`（蒂姆·伯顿）或 `Christopher Nolan`（克里斯托弗·诺兰）导演的《蝙蝠侠》(Batman) 系列电影：

在上述查询中，括号是必不可少的：没有括号时，根据运算符优先级规则，`AND` 会优先于 `OR` 执行。

如果你想检索近年来上映、且**不是**由蒂姆·伯顿执导的《猩球崛起》(Planet of the Apes) 电影，可以使用以下过滤器：

<CodeSamplesFilteringGuide3 />

<CodeGroup>

```
release_date > 1577884550 AND (NOT director = "Tim Burton" AND director EXISTS)
```

</CodeGroup>

<Warning>
[同义词字典 (Synonyms)](/capabilities/full_text_search/relevancy/synonyms)**不适用于**过滤条件。也就是说，即使你将 `SF` 与 `San Francisco` 设为了同义词，在过滤器中写 `city = "SF"` 和 `city = "San Francisco"` 匹配到的将是完全不同的字面结果。
</Warning>
