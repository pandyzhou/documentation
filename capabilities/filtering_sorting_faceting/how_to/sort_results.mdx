默认情况下，Meilisearch 专注于根据文本相关度高低排定先后次序。你可以调整这一行为，允许最终用户在发起检索时自主决定希望优先看到哪类结果。

这在电商网站中极为常见，例如用户主动点击“按价格从低到高排列”。

<Tip>
检索期排序与占位符空搜索（`"q": null` 或 `"q": ""`）结合使用时效果尤为显著，可直接充当动态数据分类列表使用。
</Tip>

## 配置开启排序能力

要允许前端用户在检索时排序，必须经过以下步骤：

1. 确定哪些字段需要支持排序（例如价格、销量、发布时间）
2. 将这些字段添加到索引设置的 `sortableAttributes` 列表中
3. 根据业务倾向，按需微调 Meilisearch 的[排序规则 (Ranking rules)](/capabilities/full_text_search/relevancy/relevancy) 顺序（可选）

<Note>
Meilisearch 按照字节数值大小对字符串进行字典序排序。大写字母会被视同小写字母参与比较，但在返回结果中依然保留原始大写外观。
</Note>

仅支持**数值型、字符串型、数值数组或字符串数组**类型的字段参与排序。

<Warning>
如果某个字段在不同文档中存在类型冲突（例如有些文档存了数字 `120`，另一些存成了字符串 `"120"`），Meilisearch 在排序时会无条件优先排列数字。为避免意外排序行为，请确保排序字段的类型在全局保持一致。
</Warning>

### 自定义排序规则在流水线中的位置（可选）

Meilisearch 默认的排序规则顺序如下：

<CodeGroup>

```json
[
  "words",
  "typo",
  "proximity",
  "attributeRank",
  "sort",
  "wordPosition",
  "exactness"
]
```

</CodeGroup>

注意：`"sort"` 默认排在第五位。这意味着它充当**“平局决胜局”**：Meilisearch 会首先确保前排结果与查询词字面高度匹配，接着在打分相同的文档中，才依照用户的 `sort` 参数排列先后。

如果你的业务更侧重于严格服从排序（例如纯粹的低价电商列表），你可以将 `"sort"` 规则在列表中向上提位。位置越靠上，对用户排序指令的遵从越彻底。

## 在检索时传入 `sort` 参数

完成配置后，在调用搜索接口时使用 [`sort` 参数](/reference/api/search/search-with-post#body-sort) 传递具体的排序指令。

每个排序条件遵循 `字段名:排序方向` 格式：`asc` 为升序，`desc` 为降序。

使用 `POST` 请求时，`sort` 接收字符串数组：

<CodeGroup>

```json
"sort": [
  "price:asc",
  "author:desc"
]
```

</CodeGroup>

数组中的排列先后至关重要：排在前面的字段具有更高优先级。在上面的例子中，如果多本书的价格相同，Meilisearch 将使用作者字段来打破平局。

## 运行时 `sort` 与自定义排序规则的区别

- **`sort`（运行时参数）**：由**前端用户**在页面上按需发起（比如用户自选升降序）。
- **自定义规则 (Custom ranking rules)**：属于**服务端固定策略**，对所有用户的搜索无差别常驻生效（例如平台运营要求新品永远优先决胜）。
