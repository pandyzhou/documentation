多索引搜索（Multi-search）允许你在**单次 HTTP 请求中同时检索多个索引**。与向每个索引分别连续发送多次 HTTP 请求相比，这种方式显著降低了客户端网络开销与请求延迟。

## 两种主要模式

| 模式 | 核心描述 | 典型业务场景 |
| :--- | :--- | :--- |
| **多索引并发搜索 (Multi-index search)** | 为每个被检索的索引返回独立的结果数组列表 | 搜索框展示分类卡片（如分别展示：匹配商品、匹配文章、匹配用户） |
| **联合搜索 (Federated search)** | 将来自所有索引的命中结果按权重综合打分，**归并混排为一个统一的列表** | 跨数据类型的大一统全局搜索 |

## 工作原理

向 `/multi-search` 端点发送包含多组独立检索条件的请求体。每组查询可以指向完全不同的索引，拥有各自独立的[过滤器 (Filters)](/capabilities/filtering_sorting_faceting/getting_started)、[排序 (Sorting)](/capabilities/filtering_sorting_faceting/how_to/sort_results)与搜索参数。

在联合搜索（Federated）模式下，Meilisearch 通过可配置的权重（Weights）机制，将多个索引的文档进行重加权打分并统一排序，让你完全掌控哪个索引的结果排在更上方。

## 异常与错误处理

<Warning>
多索引请求采用**快速失败（Fail-fast）**策略。如果在处理多索引请求中的任何一组子查询时遭遇错误（如字段未在对应索引中配置为 filterable），Meilisearch 会立即终止整个请求并返回报错。返回的错误信息仅指向遇到的第一个错误。因此，只有当列表中的每组查询全部合法时，才会返回搜索结果。
</Warning>
