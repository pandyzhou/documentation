混合搜索（Hybrid search）深度融合了两种搜索策略：[全文检索](/capabilities/full_text_search/overview)（基于关键词匹配）与语义搜索（基于上下文含义匹配）。这让用户能够两全其美，获得既在文本字面上精准吻合、又在概念语义上高度契合的搜索结果。

## 核心区别：使用的是向量嵌入模型，而非大语言模型 (LLMs)

在 Meilisearch 中，语义搜索依赖的是**向量嵌入模型（Embedding models）**，而不是耗费巨大的大语言模型（LLMs）。理解这一点至关重要：

- **向量嵌入模型 (Embedding models)**：专门将文字转换为能够捕捉语境含义的高维数字向量。它们体积小、计算快、调用成本极低。
- **大语言模型 (LLMs)**（如 GPT-4 或 Claude）：专门用于生成自然语言文本和进行复杂逻辑推理。它们体积庞大、生成速度较慢，且推理成本昂贵。

Meilisearch 在混合搜索中采用向量嵌入模型，使得搜索性能比基于 LLM 的方案**快上数个数量级，成本大幅降低**。若想了解使用大语言模型构建对话式 AI 的特性，请参阅[智能体搜索 (Agentic search)](/capabilities/agentic_search/overview)。

## 工作原理

只要在索引中配置好向量嵌入器（Embedder），Meilisearch 就会**全自动为索引中的每篇文档生成向量嵌入**。你完全无需自行编写 Python 脚本去计算或管理复杂的向量数据库。

```mermaid
flowchart LR
    A[文档数据] --> B[Meilisearch 引擎]
    B -->|全自动计算向量| C[向量索引 (Vector Index)]
    B -->|构建倒排索引| D[关键词索引 (Keyword Index)]
    E[用户搜索词] --> B
    B --> F[智能融合并加权排序]
```

在检索时，Meilisearch 会在底层**并行并发执行**关键词搜索与语义向量搜索，并通过智能打分算法将两路结果混合归并。

### 全自动向量生成流水线

Meilisearch 为你全包了整套向量流水线：

- **智能请求批处理 (Batching)**：文档会被自动合并为最优批次发送给模型服务商，最大限度减少 API 调用次数并压榨吞吐量。
- **向量缓存机制 (Caching)**：计算好的向量会被持久化缓存，只有在文档字段内容发生修改时才会重新计算。重新索引未变动的文档完全免费、零调用成本。*(注意：如果你修改了嵌入器本身的配置，如切换了模型或模版，会触发全量重新生成向量)*。
- **速率限制自动重试 (Rate limit handling)**：当远程提供商（如 OpenAI）触发 429 限流报错时，Meilisearch 会自动执行指数退避重试，无需人工干预。
- **文档模版定义 (Document templates)**：通过 [Liquid 模版语法](/capabilities/hybrid_search/advanced/document_template_best_practices)，由你精准指定将哪些关键字段拼接后送给模型生成向量。

<Warning>
部分修改嵌入器配置（例如更改 `model`、`source`、`documentTemplate`、`dimensions` 等）可能会触发全量文档的底层向量重建。在大规模数据集中，对于按量计费的云端模型服务，这可能会产生一定的 API 调用费用。
</Warning>

### 智能自适应结果融合

进行混合搜索时，Meilisearch 并非生硬地把关键词结果和向量结果拼接在一起，而是采用了一套自适应打分机制，根据用户查询词的特征，自动动态倾斜权重：

- **精准专有名词查询**（如 `"iPhone 15 Pro Max 256GB"`）：引擎会自动大幅偏向**关键词匹配**，因为完全相同的词汇在文档中明确存在；
- **描述性口语自然语言**（如 `"适合出差携带的轻薄笔记本电脑"`）：引擎会自动大幅偏向**语义匹配**，因为语境含义的契合远比死板的字面更重要；
- **模糊/通用查询**：两路策略各占半壁江山，平滑混排。

你随时可以通过 [`semanticRatio` 参数](/capabilities/hybrid_search/advanced/custom_hybrid_ranking) 手动调节偏向比率，但在大多数情况下，默认的 `0.5` 已经能够获得极佳的智能化平衡。

## 适用场景对照

| 实际业务场景 | 最佳推荐搜索策略 |
| :--- | :--- |
| 用户搜索明确的产品名称、型号或商品 SKU 编码 | **全文检索 (Full-text)** |
| 用户用自然语言或口语化描述遇到的故障与问题 | **语义搜索 (Semantic)** |
| 电商平台商品检索（用户用词千奇百怪、口语与型号混杂） | **混合搜索 (Hybrid)** ⭐️ |
| 技术文档与知识库检索（同时包含专业函数名与业务描述） | **混合搜索 (Hybrid)** ⭐️ |
| 智能客服问答与 FAQ 常见问题库 | **混合搜索 (Hybrid)** ⭐️ |

## 支持的向量模型服务商 (Providers)

Meilisearch 原生支持几乎所有主流的模型提供商，并通过通用的 [REST Embedder](/capabilities/hybrid_search/how_to/configure_rest_embedder) 支持任何符合标准规范的自定义模型 API。

### 原生集成驱动
- **OpenAI**（`openAi`）
- **HuggingFace 本地运行**（`huggingFace`，无需网络，在实例内本地计算向量）
- **Ollama 本地私有部署**（`ollama`）

### 经过官方认证的 REST 驱动
- **Cohere**
- **Mistral AI**
- **Google Gemini**
- **Cloudflare Workers AI**
- **Voyage AI**
- **AWS Bedrock**
- **Jina AI**
- **TwelveLabs (Marengo)**
- **任意自建兼容 REST API**

### 自带预计算向量导入 (User-provided embeddings)

如果你在外部已有专门的离线算法管线（如针对图像、音频提取的多模态特征向量），你可以直接通过 API 将这些预计算的高维向量写入文档的 `_vectors` 字段中。
