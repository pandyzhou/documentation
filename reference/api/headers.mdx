## 媒体类型 (Content-Type)

任何携带请求体数据（`--data-binary`）的 API 请求都必须包含 `Content-Type` 请求头，以便服务端能准确解析其格式。

Meilisearch 目前支持以下数据格式：

- `Content-Type: application/json`：标准 JSON 格式
- `Content-Type: application/x-ndjson`：换行分隔的 JSON 格式（NDJSON）
- `Content-Type: text/csv`：逗号分隔的 CSV 格式

只有[批量添加文档](/reference/api/documents/add-or-replace-documents)与[更新文档](/reference/api/documents/add-or-update-documents)端点支持接收 NDJSON 和 CSV。对于所有其他配置和控制接口，请统一使用 `Content-Type: application/json`。

## 内容压缩编码 (Content-Encoding)

`Content-Encoding` 请求头用于声明客户端发送的数据已经通过特定算法压缩。启用压缩能够显著减少网络带宽占用并成倍缩短传输耗时。而 `Accept-Encoding` 请求头则告知服务端客户端能够解压哪些算法。

Meilisearch 完整支持以下三种主流压缩算法：

- `br`：基于 [Brotli](https://en.wikipedia.org/wiki/Brotli) 算法（压缩率最高）
- `deflate`：基于 [zlib / deflate](https://en.wikipedia.org/wiki/DEFLATE) 算法
- `gzip`：基于通用的 [gzip](https://en.wikipedia.org/wiki/Gzip) 算法

### 请求体压缩发送示例

以下命令在发送大量文档前，直接通过管道将其用 gzip 压缩后再流式上传：

```bash
cat ~/movies.json | gzip | curl -X POST 'MEILISEARCH_URL/indexes/movies/documents' \
  --data-binary @- \
  -H 'Content-Type: application/json' \
  -H 'Content-Encoding: gzip'
```

### 响应体压缩接收示例

携带 `Accept-Encoding: gzip` 请求头即可通知 Meilisearch 对返回的 JSON 进行压缩：

```bash
curl -sH 'Accept-encoding: gzip' 'MEILISEARCH_URL/indexes/movies/search' | gzip -dc
```

## 检索元数据响应头 (Meili-Include-Metadata)

在发起单次搜索或多索引搜索时，你可以附带可选的 `Meili-Include-Metadata: true` 请求头：

```bash
curl -X POST 'http://localhost:7700/indexes/INDEX_NAME/search' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer MEILISEARCH_KEY' \
  -H 'Meili-Include-Metadata: true' \
  -d '{"q": ""}'
```

响应体中将包含一个 `metadata` 元数据追踪对象：

```json
{
  "hits": [ … ],
  "metadata": {
    "queryUid": "0199a41a-8186-70b3-b6e1-90e8cb582f35",
    "indexUid": "INDEX_NAME",
    "primaryKey": "INDEX_PRIMARY_KEY"
  }
}
```

| 元数据字段 | 类型 | 功能说明 |
| :--- | :--- | :--- |
| `queryUid` | UUID v7 | 单次查询的全局唯一跟踪标识符 |
| `indexUid` | String | 目标索引标识名 |
| `primaryKey` | String | 该索引当前生效的主键字段名 |
| `remote` | String | 如果请求打到了远程节点，返回对应的远程节点名 |
